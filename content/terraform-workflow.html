Inside the project

The engineering question

How can a deployment workflow manage project roles without also managing the trust and permissions that give the workflow its own access?

The implementation

Terraform manages project IAM roles and policy attachments. GitHub Actions authenticates through OIDC, saves a binary plan, and applies that artifact in a dependent job. State lives in S3 with lockfiles; workflow concurrency serializes deployments.

The Lambda component

Docker builds the function and dependency-layer artifacts. GitHub Actions runs tests and deploys through OIDC. Terraform manages the function, its role, an EventBridge schedule, and CloudWatch logging. Docker is the build environment; Lambda is the runtime.

The bootstrap role, OIDC provider, and permissions-boundary policy are configured separately.
